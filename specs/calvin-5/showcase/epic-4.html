WITH RECURSIVE chain AS (
  SELECT p.id AS plan_id, p.created_at AS published_at, s.id, s.previous_suggestion_id, s.created_at

Run it yourself

From a testbed checkout at main, with Node 26 and Chromium on PATH:

npm ci
npx vitest run --config specs/calvin-5/showcase/vitest.config.ts                    # rebuilds this page
SHOWCASE_SERVE=1 npx vitest run --config specs/calvin-5/showcase/vitest.config.ts   # and keeps the app up on http://localhost:8091

The seed is specs/calvin-5/showcase/capture.showcase.ts. It uses an embedded Postgres (the test suite's own setup), the app's own publish and commit code, the real plan workflow on Temporal's time-skipping test server, and the test fakes for email and the AI suggestion: no keys, and no email leaves the machine. It seeds:

  • Plan A, Ana's example plan, confirmed and run to the end: It's on, both reminders and the check-in. Its check-in link is then answered happened yes, then no, then attended no.
  • Plan B, Bea's copy of it, confirmed, answered attended yes first.
  • Plan C, Cal's copy, confirmed, called off from the manage page on Thu 12 Nov with every signal failing; the workflow sends "Not this time" at the 24h reminder time.

With SHOWCASE_SERVE=1 it prints a link to each state. The failure cases (a refused address, a reminder still retrying at the start, a lost signal that later arrives) are in the workflow tests: npx vitest run tests/workflow src/temporal.
